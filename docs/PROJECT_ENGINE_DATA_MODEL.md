# Project Engine — data model and security contract

## Scope

Migration `0001_project_engine.sql` establishes the first persistent domain for SynqForge: workspaces, memberships, projects, versioned artifacts, and an append-oriented activity timeline.

## Domain rules

- Projects belong to exactly one workspace.
- Workspace membership is the authorization boundary; roles are owner, admin, member, and viewer.
- Project lifecycle transitions are explicit and validated in the TypeScript domain layer.
- Product targets are web, mobile, or web + mobile.
- Artifacts are versioned by project and artifact type; prior versions remain addressable.
- Project and artifact ownership is constrained with composite workspace/project foreign keys.
- Timestamps are generated by PostgreSQL.

## Database security

Row-level security is enabled on all five tables. Every application transaction that accesses workspace data must set transaction-local context:

```sql
SELECT set_config('app.user_id', :authenticated_user_uuid, true);
SELECT set_config('app.workspace_id', :authorized_workspace_uuid, true);
```

The user UUID must come from a verified authentication session, never from an untrusted request field. The workspace must be checked against the authenticated user's membership before any operation. Use a non-owner database role without BYPASSRLS; migration credentials must not be used by the runtime.

The initial migration intentionally does not create a public unauthenticated project API. API routes are gated on the identity provider and transaction-scoped database adapter being implemented. Do not disable RLS or substitute client-supplied user IDs to make endpoints work.

## Migration

Apply migrations in lexical order using a dedicated migration identity. Back up an existing database before applying schema changes. This migration is additive and does not modify or delete application files.
